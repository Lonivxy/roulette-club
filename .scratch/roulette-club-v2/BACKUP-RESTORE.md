# Maintenance and recovery

Production remains untouched until V2 cutover. Use owner-authenticated export with all rows and migration journal, never a browser-local save as a database backup. Store private backups outside the repository in work/private-backups (ignored). Confirm maintenance prevents commands AND interest writebacks before export. Record revision, player IDs, exact-money digest and retained history/card counts. Restore the export into temporary SQLite and compare through APIs before enabling V2. Once new formal transactions exist, do not restore an old snapshot: keep maintenance on and repair forward using durable events/compensations. Native Sites applies only additive schema migrations; failed publication may already have applied them. Keep old tables and V1 source available during migration.
